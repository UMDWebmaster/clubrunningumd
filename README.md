# UMD Club Running Website

Source for the University of Maryland Club Running website: a single-page React app (Create React App) with a Firebase backend for the blog, photo archive, and a small amount of live-editable content.

> **Where do I go?** Each major folder has its own `README.md`. Start with the map below, then open the README of the folder you're working in.

## Repo map

| Path | What lives there | README |
| --- | --- | --- |
| `src/` | All application code. Entry point, router, Firebase setup. | [src/README.md](src/README.md) |
| `src/pages/` | One component per URL (Home, Races, Records, Routes, Blog, …). | [src/pages/README.md](src/pages/README.md) |
| `src/components/` | Shared UI: header, footer, route cards, calendar widget. | [src/components/README.md](src/components/README.md) |
| `src/data/` | **Hand-edited site content**: officers, races, records, routes. Most routine updates happen here. | [src/data/README.md](src/data/README.md) |
| `src/cms/` | Firestore-backed content with code defaults (Home page hero text). | [src/cms/README.md](src/cms/README.md) |
| `src/blog/` | Firestore data layer + types for blog posts and runner profiles. | [src/blog/README.md](src/blog/README.md) |
| `src/hooks/` | Custom hooks: Firebase auth, GPX route previews. | [src/hooks/README.md](src/hooks/README.md) |
| `src/internalTools/` | Localhost-only admin pages (photo archive entry, records editor). | [src/internalTools/README.md](src/internalTools/README.md) |
| `src/CSS/` | Per-page stylesheets (plain CSS alongside Tailwind). | [src/CSS/README.md](src/CSS/README.md) |
| `src/Pictures/` | Images imported by pages and data files. | [src/Pictures/README.md](src/Pictures/README.md) |
| `public/` | Static files served as-is: `index.html`, race schedule JSON, GPX route files. | [public/README.md](public/README.md) |
| `server.js` | Optional local Express API for reading/writing `public/races-data.json`. | see [public/README.md](public/README.md#races-datajson) |

Root config files: `package.json` (deps + scripts), `tailwind.config.js` (Maryland color palette and fonts), `tsconfig.json` (lets `.ts` files under `src/blog` compile alongside JS).

Not source, safe to ignore: `build/` (generated by `npm run build`, git-ignored), `node_modules/`, `dist/output.css` (old Tailwind CLI output, not imported anywhere), `.vs/` (Visual Studio workspace cache that was committed by accident), `tmp_before.txt` (scratch copy of an old `Home.js` snippet).

## Architecture at a glance

```
Browser
  └─ src/index.js → src/App.js (React Router, Header/Footer wrap every page)
        └─ src/pages/*  ── render ──▶ src/components/*
              │
              ├─ static content ........ src/data/*.js|json, src/Pictures/*  (bundled at build time)
              ├─ static fetch .......... public/races-data.json, public/routes/*.gpx
              ├─ Firestore ............. siteContent/home (cms), posts + profiles (blog)
              ├─ Realtime Database ..... archives/photos (Photos page)
              └─ third-party ........... Google Calendar API, Google Apps Script (newsletters),
                                         Google Forms, embedded iframes
```

Most of the site is **static content compiled into the bundle**. Changing officers, records, routes, or race schedules means editing a file and pushing — no database involved. Only the blog, photo archive, and Home hero text live in Firebase.

## Getting started

```bash
git clone https://github.com/UMDWebmaster/clubrunningumd.git
cd clubrunningumd
npm install
npm start            # http://localhost:3000
```

Other scripts:

| Script | Does |
| --- | --- |
| `npm start` | CRA dev server on port 3000. |
| `npm run build` | Production build into `build/`. |
| `npm run start-server` | Runs `server.js` (races API) on port 3001. |
| `npm run dev` | Both of the above together (needs `concurrently`, already a devDependency). |

### Environment variables

Firebase config is read from `.env` (git-ignored). Without it, static pages still render but the blog, photo archive, and CMS content fall back or fail. Ask the previous webmaster for values.

```
REACT_APP_FIREBASE_API_KEY=
REACT_APP_FIREBASE_AUTH_DOMAIN=
REACT_APP_FIREBASE_PROJECT_ID=
REACT_APP_FIREBASE_STORAGE_BUCKET=
REACT_APP_FIREBASE_MESSAGING_SENDER_ID=
REACT_APP_FIREBASE_APP_ID=
REACT_APP_FIREBASE_MEASUREMENT_ID=
```

The Realtime Database URL is hard-coded in `src/firebaseConfig.js`. The Google Calendar API key is hard-coded in `src/pages/Home.js`.

## Common tasks (cheat sheet)

| I want to… | Edit |
| --- | --- |
| Update officer bios | `src/data/officers.js` (+ photo in `src/Pictures/`) |
| Update the race schedule | `public/races-data.json` (live) **and** `src/data/races.js` (fallback) |
| Add/update a club record | `src/data/records.json` (or use `/private/recordManager` locally) |
| Add a Terrapin Invite meet record | `src/data/terp-invite-records.json` |
| Add a running route | `src/data/routes.json` + GPX file in `public/routes/` |
| Add a season's training plan | `seasons` array at the top of `src/pages/Workouts.js` |
| Add a photo album link | `/private` on localhost (writes to Firebase) |
| Change Home hero text | Firestore `siteContent/home`, or defaults in `src/cms/contentDefaults.js` |
| Add a nav link | `src/components/Header.js` (desktop **and** mobile lists) |
| Add a new page | New file in `src/pages/` + `<Route>` in `src/App.js` |
| Update Terrapin / Old Bay invite info | `src/pages/HomeMeet.js` / `src/pages/XCHomeMeet.js` |

## Committing changes

- Don't commit if there are errors — run `npm start` (or `npm run build`) first.
- Then:
  ```bash
  git add .
  git commit -m "MESSAGE"
  git push
  ```
- Images in `src/Pictures/` go straight into the bundle. Resize/compress photos before adding them (several existing ones are 10–20 MB).
